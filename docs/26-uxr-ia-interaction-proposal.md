# 26 — UX-R 交付二：信息架构与交互重设计提案（微信/QQ 对照）

> 批次：UX-R（docs/briefs/uxr-design.md §2）。本文件=提案与理由，供主控裁决；规范终稿在 docs/24-mobile-ux-redesign.md。零编码；现状以代码（main=de60406）+ 既有截图为准。

## 1. 现状盘点（导航 IA 底账）

### 1.1 现结构（MainTabs.kt:47-118 + MainActivity.kt:143-247）

```
首启流：gateway 配置页 → pairing 配对页 → main（四标签）
底栏四标签：会话 | Agents | 诊断 | 设备
顶部常驻：连接状态条（含「网关配置」入口）
堆叠目的地：session/{id} 详情、children/{id} 子会话、remote/{id} 全屏 WebView、remote-manage 条目管理
```

| 标签 | 实际内容 | 消费级问题 |
|---|---|---|
| 会话 | provider 过滤 chips + 会话行（头像/标题/状态徽章/mode 徽章/stale）+ 顶部「ZCode 工作区」智能卡 + 显示归档开关 + 演示模式开关 | 行内三个徽章（状态/ mode/stale）无主次；标题用「会话」而聊天软件惯用「对话」；空态无引导 |
| Agents | 英文标题 + WakeHostCard（唤醒 Windows）+ provider 卡（诚实文案/granted 串/原因卡/启动托管会话/打开遥控） | 整页为「能力披露」组织，不是「能做什么」组织；英文 tab 名；启动入口藏在卡内展开面板 |
| 诊断 | 本机 WS 状态 key=value + 桌面 /v1/diagnostics 原始投影 | 纯工程排障面，挂在一级导航——消费级产品从不给一级 tab |
| 设备 | 本机 deviceId/网关名/tokenVersion + 服务端状态 + 撤销本设备 | 一级 tab 只为一个低频操作（解绑）服务；令牌版本等开发者字段直出 |

### 1.2 其他结构性现状

- 连接状态条（ConnectionStatusBar）占据每个 tab 顶部一行，六态文案含「心跳/退避/Relay」（docs/25 M5-M12）。
- 「ZCode 工作区」智能卡固定在会话列表顶部（WorkspaceLinkCardView），承担遥控主入口（T1 批裁决），管理入口小图标进 remote-manage。
- 演示模式入口有两处（SessionsScreen 标题行开关 + GatewayConfigScreen 底部按钮），夹具纪律存在但「演示数据·开/关」「夹具」用词是内部语。
- 通知权限入口在 GatewayConfigScreen 底部（U1-M5 修复产物）。

## 2. 提案总览：底栏三标签（对话 / 助手 / 我的）

```
┌────────────────────────────────────────────┐
│ 状态 chip：● 已连接（点开=连接状态页）            │  ← 常态一行，非阻断
├────────────────────────────────────────────┤
│  [对话]            [助手]          [我的]     │  ← 底栏三标签
└────────────────────────────────────────────┘
```

| 新标签 | 承接（迁移映射） | 取舍理由 |
|---|---|---|
| **对话** | 现「会话」全量 + ZCode 工作区智能卡（保留为置顶卡） | 聊天软件主页面心智；会话=记录（偏工程），对话=正在进行的事（偏消费） |
| **助手** | 现「Agents」页改名重排：AI 助手卡（头像+名+可以对话/仅查看+开始对话）+ 唤醒电脑动作 | 「Agents」是行业词不是用户词；把「能力披露」重组为「选一个助手、开始对话」 |
| **我的** | 现「设备」+「诊断」+ 连接设置（gateway）+ 通知设置 + 演示模式 + 开发者折叠 | 微信「我」页范式：一切低频、配置、状态类收容于此；一级导航从 4 减到 3 |

迁移成本评估：

- 对话 tab：改名+列表行重排（P2）；数据面零改动。
- 助手 tab：ProviderCard 重排（P2）；数据面（/v1/agents）零改动。
- 我的 tab：合并三个屏的入口（P2）；诊断/设备/连接设置三屏本体保留，仅移动挂载点。
- 深链与路由（devhub://session/{id}、remote/{id}、remote-manage）全部保留，零破坏。

## 3. 三屏文字线框

### 3.1 对话（微信聊天列表形态）

```
├──────────────────────────────────────────┤
│ [K] Kimi 助手        正在等待你的输入…  ⏰  │ ← 助手头像+最近消息预览+状态角标
│      「任务 xxx」        10:24            │
├──────────────────────────────────────────┤
│ [C] Claude Code      任务已完成 ✓    昨天  │
├──────────────────────────────────────────┤
│ [Z] ZCode            只能查看 · 9月12日    │ ← observed 会话角标（诚实不消失）
├──────────────────────────────────────────┤
│ 空态：这里会显示电脑上的 AI 对话。             │

└──────────────────────────────────────────┘
长按行：归档 / 取消归档 / 删除（保留 R3 交互）
```

- 列表行信息密度对齐微信：一行主体（头像+标题+预览+时间+角标）。现状的三徽章堆叠（StatusBadge+ModeBadge+stale）收敛为：**一个状态角标**（waiting/approval 高亮，沿用 X1 九值人话）+ 行副标题放预览；「仅查看」「信息可能不是最新」降为副文案，不再占独立徽章位（docs/25 X2/S6/D3）。
- 时间格式 TimeFmt 已有 mdHm，直接复用；最近消息预览取消息缓存尾条（数据面已有 Room 缓存，零新接口）。
- provider 过滤 chips 保留（数据驱动，U2-M5 渐隐已修），置于列表顶部次级行。

- capabilities 二态主显示：「● 可以对话（managed）/ ○ 仅查看（observed 及未授权）」，attached 按 granted 投影归入可以对话或仅查看，细节进 ⓘ（docs/25 D22，任务书 §1 映射）。
- 「开始对话」一键化：现流程=展开面板→填任务→确认启动（三步）；提案=点按钮即展开单输入框+键盘弹起（两步）；命名全链人话（spawn→新建对话/开始对话）。
- 唤醒卡只在「电脑不在线且云中转已连接」时置顶出现（减少常态噪音）。

## 4. 关键流程重排

### 4.1 首次连接（现：gateway 表单 → 配对码）

现状步数（首装）：启动 → Remote Gateway 配置页（模式选择+host/port/relay endpoint/指纹）→ 保存并继续 → 配对页（输 8 位码）→ 配对 → 安全须知 → 主页。**约 7 个认知节点**，且第一屏满是 endpoint/SPKI/端口（docs/25 §5/§6）。

提案（P3）：

```
启动 → 「连接电脑」（一页完成）
  步骤 1：手机和电脑连同一个 Wi-Fi？ ——是→ 填电脑地址（默认自动补端口）｜否→ 云中转（填服务器地址）
  步骤 2：输入电脑上显示的 8 位配对码 → [连接]
  成功 → 安全须知（一次）→ 对话页（空态引导）
  底部：「高级选项」折叠（端口/pairingId/证书指纹/演示模式）
```

- 填码即连即现网主流程（code-only，AC7b 已实现），本提案只是**把两页合一页 + 高级项折叠**，服务端零改动。
- 扫码即连：桌面端展示配对码二维码 + 手机扫码（-camera 权限）为 P3 增强项，依赖桌面端出码（跨端改动，另立批裁决）。
- 三态区分文案随流程内嵌（docs/25 §14）：连不上时明确「电脑没开机 / 网络不通 / 码过期」三选一提示。

### 4.2 启动对话（现：Agents 卡展开面板）

提案（P2）：助手页一键「开始对话」→ 单输入框 →「开始」。模式选择自动化：managed 自动静默选择；无任何 managed provider 时按钮不出现（诚实纪律，绝不显示不可用入口——InteractionHonesty.canSpawnManagedSession 门保留）。

### 4.3 空态与错误态通用律（P1 即生效）

每屏空态必须含「一句事实 + 一步动作」：

| 屏 | 空态事实 | 下一步动作 |
|---|---|---|
| 对话 | 还没有对话记录 | [去助手页开始] / 检查电脑连接 |
| 助手 | 还没有发现 AI 助手 | [重新扫描] / 检查电脑 DevHub 是否运行 |
| 我的-电脑 | 未连接 | [去连接] |
| 电脑页面管理 | 还没有条目（现 R3 已合格） | 从剪贴板粘贴（保留） |
| 子任务 | 没有子任务（C2） | [返回对话] |

错误态统一 ErrorPresentation（U1-M3 已建），补齐：每处错误面附「重试」或「诊断」动作出口（A3/S8 等清点项）。

## 6. 分级落地路线（P1 文案层 / P2 导航 IA / P3 流程引导）

### P1：文案层（改词表即全局生效；对应 docs/25 全部 ★ 项）

- **改动面**：11 个屏 + 8 个组件内的硬编码字符串替换；:core 文案常量（InteractionHonesty/CapabilitiesExplain/ErrorPresent 微调/RelayPairing 尾码折叠/EventNotification/SessionListOps 微调）；strings.xml 增补（通知文案）；ConnectionManager.diagnosticsSnapshot 人话化拆分（人话行+technical 行）。硬编码→strings.xml 集中化可选（建议做，为后续 i18n 留路）。
- **风险**：低。:core 文案常量有单测直锁（ CapabilitiesExplain/ErrorPresent/InteractionHonesty/SessionListOps 均有测试），改词需同步改测试断言——属预期联动，不改断言语义只改期望串。诚实纪律回归风险点：H1/H6/H9/X2 等锁定语义文案改写后必须逐条过「能力如实披露」复核（不可逾越节 #3）。
- **验收口径**：① grep :app+:core 用户面字符串无 Relay/心跳/granted/commandId/managed/observed/provider/endpoint/SPKI/夹具/TTL 直出（折叠区白名单除外：D23/G12/P7 技术原文区）；② 全屏截图走查（模拟器归 RD 复验批）对照 docs/25 逐条销账；③ :core + :app 单测全绿；④ 三态文案矩阵（docs/25 §14）逐态可复现。

### P2：导航 IA（底栏四→三；诊断/设备并入我的；状态条降级 chip）

- **改动面**：MainTabs.kt 重构（三 tab + 路由）；诊断/设备两屏挂载点迁到「我的」；「我的」新页（聚合卡+折叠组）；SessionsScreen 列表行重排（预览+角标，数据用既有 Room 缓存）；AgentScreen 卡重排；AppState/路由 deep link 不动。
- **风险**：中。导航回归（rememberSaveable tab 状态、返回栈、deep link devhub://session）、列表行渲染性能（预览需查消息缓存尾条——建议 Room 里预聚合，避免每行子查询）。U-Aud 已修面（U1-M1 横屏、U2-M5 渐隐等）需回归验证不推翻。
- **验收口径**：① 任一功能 ≤2 tap 可达（诊断/连接设置/解绑/演示模式从「我的」一步进）；② deep link 冷启/热启直达会话详情回归通过；③ 会话列表滚动 60fps 抽测；④ 四标签→三标签迁移后 U-Aud 走查七项任务清单全过。

### P3：流程引导（连接流合一页、启动对话一键化、空态全引导、唤醒联动、扫码即连[跨端另裁]）

- **改动面**：新建「连接电脑」单页流（组合现 GatewayConfig+Pairing 两屏表单为分步向导，逻辑复用 RelayEndpoint.parse/claim/RelayPairingClient 零改）；助手页开始对话动线重排；各屏空态 CTA 接线；唤醒卡联动电脑状态卡。扫码即连需桌面端配对码二维码输出+手机扫码库——跨端改动，建议另立批裁决。
- **风险**：中高。首启流是转化咽喉，配置表单合并不得损失 local/relay 显式选择纪律（绝不字段嗅探，M3-C3a 裁决）与 wss 强制校验（保存与连接两层同函数）；配对失败清码重输（M3-C6c #6）等防呆必须保留。
- **验收口径**：① 首装 funnel e2e：安装→看见对话列表 ≤ 5 次人工输入/点击（现约 9）；② 三态错误（电脑没开/网络不通/码错）e2e 各演练一例且文案命中 docs/25 §14；③ 高级项全部仍可达（开发者折叠展开后功能等价现网）；④ local/relay 切换+保存重连（断旧连新 W-R6）回归通过。

## 7. 取舍与未决（留主控裁决）

1. 「会话→对话」全量改名波及测试与文档措辞——建议 P1 一次到位（词表统一）。
2. 状态条降级 chip 后，relay 降级态（电脑离线+命令排队）是否保留琥珀横幅常驻？建议：保留横幅（容错降级纪律，docs/19 §7.3），仅文案人话化（M5）。
3. 扫码即连（P3 增强项）依赖桌面端出码，是否纳入本轮实现批由主控裁决。
4. 端口输入是否收进高级折叠（G6）——local 模式默认 8746 通常无需改，建议折叠；主控终裁。
5. 「演示模式」是开发者联调工具，是否从「我的」再降一级进「开发者选项」——建议是；但演示模式夹具纪律标注（S3）必须保留显著。
