# UX-R 批任务书：App 消费级交互重设计——审计+设计规范（设计批，零编码）

> 背景：用户裁决「app 交互太反人类，到处看不懂的术语（心跳/relay…），像半成品，交互性为 0，参考微信/QQ 大厂交互」。这是产品方向级指令：把工程师视角的 App 改成消费级交互。本批=审计+设计规范产出，**零编码**；主控裁决规范后另立实现批。基线 main=KC 合并后 main。

## 0. 工作区与纪律

- worktree：主仓根 `git worktree add worktrees/uxr-design -b agent/uxr-design main`（纯文档+读码，可不装依赖）。
- 每 commit 即 push 分支（直连优先 socks5h://127.0.0.1:1081 兜底）；绝不 push main；凭据三零。
- **零编码零模拟器**（模拟器归并发 RD 复验批）；UI 现状以代码字符串+既有截图（acceptance/agents-mobile/ux-audit-20260912/ 28 张+mobile-chat-relay-e2e/shots 14 张）为准。
- 红线（设计必须遵守，写进规范「不可逾越」节）：不伪造状态（离线不能装在线、无证据不编造）；凭据纪律（尾 4 位掩码等）；会话门语义（observed 只读）不因文案改而模糊；协议/字段零改动（本专项纯呈现层+交互层）。

## 1. 交付一：全量术语与文案清点（人话词表）

- 清点 :app 全部用户可见字符串（screens/components/错误呈现/通知/空态），逐条登记：现文 → 出现位置（文件:行号）→ 问题定性（协议词泄漏/机翻腔/直译/无引导）→ **人话提案**。
- 重点映射（起点，非全集）：Relay→「远程连接/云端中转」；心跳 30s→隐藏，状态只剩「已连接/连接中/已断开」；token rotation/令牌版本→隐藏进开发者折叠；capabilities/mode → 「可以对话/仅查看」两态人话；provider → 「AI 助手」（Kimi 助手/Codex 助手/…）；gateway/endpoint/SPKI/指纹→配对流程收敛，高级项折叠；spawn → 「新建对话」；session_mode → 隐藏；gateway_config 等设置键名→界面文案与键名解耦。
- **约束**：人话不得损失可判断性——出错时用户要能区分「电脑没开/网络不通/还没配对」，方案给出每态文案。

## 2. 交付二：信息架构与交互重设计提案（微信/QQ 对照）

1. **导航 IA**：现底栏四标签盘点 → 提案消费级结构（候选：**对话**〔会话列表仿聊天列表：助手头像+最近消息预览+时间+未读/状态角标〕/**助手**〔AI 助手卡片：启动新对话入口〕/**我的**〔电脑连接状态卡「办公室电脑 · 在线」+设备+设置〕）——给出取舍理由与迁移成本。
2. **关键流程重排**：首次配对（现 endpoint 手填+指纹 → 提案：填码即连/扫码即连，高级项收「开发者选项」折叠）；启动对话（现 Agents 卡术语卡 → 提案：助手页一键「开始对话」，模式选择人话化或全自动）；错误态/空态（每屏空态必须有下一步引导动作）。
3. **对照分析**：微信/QQ 各举 3-5 个可迁移模式（聊天列表形态/会话项信息密度/设置渐进披露/首次引导/连接状态表达），说明怎么落到本 App。
4. **分级落地路线**：P1 文案层（改词表即全局生效）/P2 导航 IA/P3 流程引导——每级改动面+风险+验收口径，供主控排批。
