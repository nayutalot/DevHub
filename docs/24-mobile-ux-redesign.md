## 1. 范围与不可逾越（红线，任何实现批必须逐条过）

1. **不伪造状态**：离线不能装在线、无证据不编造。人话化只改「怎么说」，绝不改「说什么」。 relay 降级态（已连中继+电脑离线）必须保持为显性异常态（琥珀底），绝不显示为正常态（docs/19 §7.3 容错降级纪律）。
2. **凭据纪律**：Token/配对码/指纹/URL 令牌零明文展示（尾 4 位掩码或折叠区原样保留的既有纪律不变）；日志零内容（R5.1 打点纪律）；清点/截图涉 token/key 字样只记位置不录值。
3. **会话门语义不因文案模糊**：observed=零控件只读（ControlGate 现状）；「可以对话/仅查看」两态人话必须与 capabilities.mode 真值一一对应（managed/attached→可对话侧、observed→仅查看），绝不把不可用画成可用（docs/17 §3 #2、InteractionHonesty 红线）。observed + waiting_input 的锁定徽章语义（等待输入·只读）保持。
4. **协议/字段零改动**：本专项纯呈现层+交互层。endpoint 解析（RelayEndpoint.parse 保存与连接两层同函数）、wss 强制、claim 时序、WS 帧、REST 契约、idempotency、QueueReplay、token rotation 单调门一律不动。
5. **诚实折叠、零吞码**：技术原值（mode/granted/evidence、错误码、异常串、心跳/seq、key=value 诊断）从用户常态面移入「技术细节/开发者选项」折叠区——翻译不删除。
6. **夹具（演示模式）纪律**：显式进入、全界面显著标注、绝不伪造控制通道（canSpawnManagedSession 夹具恒 false）。演示模式用词人话化但标注不弱化。
7. **零编码零模拟器**（本设计批）；实现批的模拟器验证归并发 RD 复验批口径。

### 2.2 三态可判断性（硬约束，任务书 §1）

人话化不得损失故障判断力。用户必须能区分以下三态，每态有互斥文案+动作出口：

| 态 | 代码真值 | 常态面文案（状态条/电脑卡） | 动作出口 |
|---|---|---|---|
| 还没配对 | ConnState.Unpaired / 无凭据 | 还没连接电脑：先在电脑上生成配对码 | 「去连接」→ 连接流 |
| 网络不通 | Backing+lastError（超时/解析/拒绝族）；探测 IOException | 连不上：检查手机网络或电脑是否开机（第 {n} 次重试，约 {x} 秒后） | 「诊断连接问题」 |
| 电脑没开/不在线 | relay Connected + upstream disconnected；local ConnectException | 云中转已连上，但电脑不在线——消息会在电脑上线后自动送达（local：电脑连不上，请确认电脑已开机且 DevHub 在运行） | 「唤醒电脑」（relay）/「重试」 |

详细数值（心跳/seq/attempt/lastError）全部保留在「连接帮助→技术详情」折叠区，可判断性无损失。

## 3. 信息架构（文字线框，终稿=三标签）

详案与取舍理由见 docs/26 §2/§3。本节为规范形态：

```
首启（未配对）：连接电脑（单页流，P3 合一页；P1/P2 期维持 gateway→pairing 两页+文案人话化）
主框架：
  顶部：状态 chip（● 已连接 / ◌ 连接中 / ↻ 重试中(第n次) / ✕ 未连接 / ⚠ 云中转已连上，电脑不在线）
        ——点开=「电脑连接状态」页（现诊断页人话化，Dg1-Dg7）
  底栏：对话 ｜ 助手 ｜ 我的
  堆叠：对话/{id} 详情（保留气泡流/滑条/子任务入口）、children/{id}、remote/{id} 全屏、
        我的→电脑页面管理（remote-manage）、我的→连接设置、我的→这台手机
```

- **对话**：置顶「电脑」（ZCode 工作区卡，灰底置顶样式）+ 会话行（助手头像+标题+最近消息预览+时间+状态角标；provider 过滤 chips 次级行；长按 归档/删除 保留）。
- **助手**：AI 助手卡（头像+名+●可以对话/○仅查看+一句能力说明）+「开始对话」+（zcode 卡）「打开电脑页面」+ 条件置顶「唤醒电脑」卡。
- **我的**：电脑连接状态卡（名字可后缀如「办公室电脑·在线」——名字取 deviceName，无则「我的电脑」）→ 连接设置/诊断连接问题/唤醒电脑；「这台手机」（解绑）；消息提醒（通知权限）；电脑页面管理；演示模式；开发者选项（折叠：设备ID/令牌版本/心跳与seq/指纹/诊断原文）。
- 深链与路由全保留（devhub://session/{id}、remote/{id}、remote-manage）。

## 4. 关键流程（文字流程图）

### 4.1 首次连接（P3 目标态）

```
启动 → 连接电脑页
  ├─ 选方式：同一网络（默认）｜云中转   ← 显式选择纪律保持（绝不字段嗅探）
  ├─ 填地址（local：电脑地址[+端口进高级]；relay：服务器地址 wss:// 强制校验）
  ├─ 输 8 位配对码（5 分钟内有效）→ [连接]
  │    失败三态文案：码不对/过期 → 电脑上重新生成；连不上 → 电脑没开机 or 网络不通（§2.2）
  ├─ 成功 → 安全须知（一次）→ 对话页（空态引导：去助手开始第一个对话）
  └─ 高级选项（折叠）：端口 / pairingId / 证书指纹 / 演示模式
扫码即连（增强项，跨端另裁）：桌面出二维码 → 手机扫码 → 同上自动填码。
```

### 4.2 启动对话

```
助手页 → 助手卡 [开始对话] → 输入第一条消息（placeholder：想让它先做什么？）
  → [开始] → 「正在创建…」→ 跳入新对话详情（气泡流）
  拒绝三态人话（H19）：通道不可用或达上限 / 暂不支持手机开始 / 未验证先在电脑刷新（码进折叠）
  电脑离线：请求暂存，上线后自动开始（A18）；绝不伪成功。
```

### 4.3 错误与空态通用律

- 错误面 = 一句人话 + 建议动作 +（有则）「技术细节」折叠（ErrorPresentation 既有组件，U1-M3 产物，全局强制）。
- 空态 = 一句事实 + 一步动作（docs/26 §4.3 五屏表格为准）。

## 6. 微信/QQ 模式迁移清单（规范约束）

1. 聊天列表行形态（微信）：头像+标题+预览+时间+角标（对话 tab 主行）。
2. 置顶卡（微信文件传输助手）：「电脑」置顶卡承载遥控+状态。
3. 「我」页渐进披露（微信）：低频/配置/开发者全收「我的」，开发者选项三级折叠。
4. 状态表达克制（微信）：常态一行 chip；异常显性但不阻断。
5. 待办角标（QQ）：waiting/approval 会话高亮角标。
6. 「我的电脑」设备会话心智（QQ）：电脑=联系人。
7. 破坏操作二次确认红字（QQ）：既有确认族保留并全局统一。

## 9. 词表终稿裁决点（留主控）

1. 「会话→对话」「配对→连接」「撤销→解绑」三处全局改名的最终定名。
2. 「云中转」vs「云端连接」二选一（本文档暂用「云中转」）。
3. attached 模式的二态归类细则（按 granted 含 reply 与否）在 ⓘ 弹层的展开规则。
4. 扫码即连是否纳入实现批（跨端）。
5. 端口输入、演示模式入口在「我的」页的最终层级。
