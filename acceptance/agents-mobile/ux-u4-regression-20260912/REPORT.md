## 项2 T1 Ready 态实拍——FAIL（结构性，如实报）

**实测**：配对成功后（WS「已连接·心跳 30s」正常），会话列表顶部「ZCode 工作区」卡始终为 **Queued 态**（「桌面 ZCode 链路未就绪：请求已排队，就绪后自动送达」，`06`）；切 Agents 再回会话页触发自动重取链（SessionsScreen LaunchedEffect → WorkspaceLinkController.request()）后**仍 Queued**（`07`）；遥控管理屏同态、无重试钮（重试=重进屏自动请求，`08`）。卡片在 Queued 且无既往条目时**不可点击**（`06` 实测 enabled=false），故「点击 → WebView 加载 → 返回键页内先退」三步本环境不可达，未拍摄。

**根因（只读源码定位）——与桌面 ZCode 链路是否存活无关，本地模式结构性只有 Queued**：
- App `WorkspaceLinkController.kt:113-116`：`submitWorkspaceLink` 走 relay 帧面，local 模式无 relay WS 一律 Queued；
- App `ConnectionManager.kt:1188`（本地 WS 上发 relay command 帧）+ `:1330-1341`（无 ack → 超时 → 入队 → Queued）；
- 桌面 `gateway/ws.ts`（onText）：本地 WS 协议仅 hello/sync/event/ack，**未知帧型静默忽略**——command 帧在本地模式永无 command_ack 回程；
- App `ConnectionManager.kt:1403-1410`：本地补发轮对 `workspace_link` 结构化落败 `COMMAND_NOT_EXECUTABLE (local face)`（仅 relay 命令面存在，docs/18 §5.3）。

**判定**：任务书前提「桌面 ZCode 链路现存活 → 卡应自动取链转 Ready」在本 APK 的**本地模式**下不成立——Ready 与 Unavailable 两态均不可达，恒 Queued。桌面链路存活只影响 relay 模式下的命令面回程。**本批未擅自切换 relay 模式**（需生产 relay endpoint+指纹入 App，超出只读授权面且徒增凭据暴露面），如实报 FAIL。修复方向二选一：①local 面给 workspace_link 一条 REST 直查路径；②文档明示 T1 卡仅 relay 模式可用并把 Queued 文案改成分模式诚实文案。

**部分修复确认（非该项判据，顺带留证）**：P1-4 的 Queued 文案已换新（「桌面 ZCode 链路未就绪：…」，非旧「电脑离线」），与心跳横幅不再用语冲突。
